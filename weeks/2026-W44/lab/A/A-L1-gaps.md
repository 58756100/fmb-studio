# A-L1 gaps log (lane A, blind): where the spec is silent, the literal reading taken

Phase 1 (storyboard stills, hook 1). Each entry: what the spec does not say -> what we did.

## Shared with L2/L3
1. **Which cut-out is "240Z" / "brake kit".** Kit file names are numbered -> 240Z = `car-05` (orange S30), brake kit = `part-06` (rotor + caliper). Studio cut-outs only; no install photos.
2. **"Photo" vs "cut-out".** BEATS say "photo"; VISUAL SPEC says "full car cut-out". -> The cut-out sits inside a rectangular frame filled with the secondary panel colour (#303832) and a thin paper-tint outline, so it reads as a photo while staying a flat asset.
3. **What the emphasis colour (#E6A16A) is for.** Not assigned. -> Field labels, the DEMO BUILD tag, the active/new element (part-field edge, photo-thumbnail border, URL field border) and connecting lines. Headlines stay in the text colour.
4. **On-screen text vs record fields.** Rows like "PART: BRAKE KIT" are both on-screen text and a record field. -> The on-screen text is always the headline (Barlow Condensed Bold, top of the essential box, y≈254); the mockup shows the same field in UI type (label in Plex Mono, value in Source Sans 3).
5. **Headline size.** Range 80–104 px. -> 96 px, auto-reduced (never below 80) when a line would pass x=880; two-line questions are explicit line breaks.
6. **Subtitle styling.** Only position and size given. -> Source Sans 3 Semibold 52 px, text colour, centred in x 96–880 / y 1220–1410, no box. Sentence case exactly as the VO column.
7. **Subtitles on "—" seconds.** -> No subtitle while there is no speech (24 s and 27 s stills have none). On-screen headline is held.
8. **"UI fields ≥44 px".** -> Every text element inside a mockup/record (labels included) is ≥44 px; values 48 px.
9. **DEMO BUILD marking.** -> An outlined Plex Mono "DEMO BUILD" tag on every record/mockup from 10 s on (no record content exists before 10 s).
10. **Area below y=1430.** Spec puts essential text above it. -> Left as plain background (no text, no decoration).
11. **Follow line style.** "Small follow line", no size. -> Source Sans 3 Semibold 48 px (UI/subtitle font), two lines "FOLLOW FuelMyBuild / BETTER BUILD RECORDS", placed between the record and the subtitle band (y≈1080), since subtitles occupy 1220–1410 during 25–27 s.
12. **Still timing.** -> Each still shows the settled state of the beat that starts at that second.

## L1-specific
13. **"Blank evidence panel".** -> A paper-coloured (#F2EBDD "text/paper") sheet over the photo's lower half with four empty ruled lines and no text, so it reads as an empty record without adding words.
14. **Requester labels (3–5 s).** Not in a key still; planned as Plex Mono labels "INSURER" / "APPRAISER" beside the panel with emphasis-colour pointer lines.
15. **Brand, garage names.** Given as DEMO BRAND A / DEMO GARAGE A -> shown as "Demo Brand A", "Demo Garage A" in record fields (headline keeps the spec's caps).
16. **Date format inside the record.** -> "OCT 12, 2026" in Plex Mono, exactly as the on-screen text.
17. **Build title.** L1 never names one. -> None shown; the page header carries only the FuelMyBuild wordmark and the DEMO BUILD tag.
18. **Public URL path.** "Example path labelled DEMO", no path given. -> `fuelmybuild.com/demo-240z` under a "PUBLIC URL · DEMO" label. The real URL scheme is not verified.
19. **Section names on the build page.** -> "PARTS" for the parts section; the dated log row is shown by its date. No other sections.
20. **Thumbnail at 13 s.** "Supplied kit photo fills the log's thumbnail" -> the right-hand kit image moves into the log's PHOTO thumbnail (so "part thumbnail right" in the layout is satisfied by the thumbnail). Studio image on a DEMO BUILD record, not presented as an install photo.
21. **"Joined by a simple line" (20–22 s).** -> 6 px emphasis-colour vertical line from photo to record.
